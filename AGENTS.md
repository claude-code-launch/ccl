# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Common Development Commands

Go 1.26 (see `go.mod`). CI (`.github/workflows/ci.yml`) is the source of truth:

```bash
gofmt -l .                 # must be empty
go test -race ./...
go vet ./...
go build ./...
```

Local / targeted:

```bash
go build -o /tmp/ccl-verify .
go test ./cmd -run TestRunAuthGrokWithoutAliasDerivesName
go test ./internal/oauthproxy ./internal/claude ./cmd
```

Release binary (matches CI): `scripts/build-release.sh` with `GOOS`/`GOARCH`/`OUTPUT`/`VERSION`; uses `-trimpath -ldflags="-s -w -X github.com/claude-code-launch/ccl/cmd.Version=..."`. `GOOGLE_OAUTH_CLIENT_ID` / `GOOGLE_OAUTH_CLIENT_SECRET` inject the Google Drive Desktop client (required by the release workflow; dev builds use `CCL_GOOGLE_OAUTH_CLIENT_ID/_SECRET`).

Web UI (`internal/webui/frontend`, Node >= 22):

```bash
npm ci && npm test && npm run build   # build writes ../web, which must be committed
npm run dev                           # hot reload against a running `ccl web` (CCL_WEB_URL)
```

There is no Makefile or golangci-lint config.

### Do not run the `ccl` binary as a test harness

Unknown first args are **not** errors: `cmd/root.go` forwards them to Claude Code and starts a billed session (`ccl resume`, `ccl -p "..."`, a quoted typo like `./ccl "provider --help"`). Prefer `go test` and `--help` with unquoted subcommand args. `ccl statusline` is intercepted before config load.

Bare `ccl lang` is interactive; use `ccl lang zh` / `ccl lang en`. Do not run `set` / `map` / `use` / `oauth` / `cloud` / `provider` (mutating subcommands) against the developer's real `~/.ccl/` unless asked.

`~/.ccl/config.yaml` stores plaintext API keys — do not dump it.

## High-Level Architecture

`ccl` launches Anthropic's Claude Code CLI against other model sources. Claude Code always speaks Anthropic Messages; ccl either points it at a real Anthropic-compatible gateway or starts a **127.0.0.1** loopback runtime that translates.

Data flow:

`main.go` → `cmd/` (Cobra + TUI) → `internal/config` + `internal/provider` → `internal/providersession.Prepare` → `internal/claude` (temp `settings.json`, env cleanup, `claude --settings ...`) → `internal/oauthproxy` when a proxy is required.

`ccl acp` wraps **`@agentclientprotocol/claude-agent-acp`** (Node.js >=22; CI pins 0.90.0). The upstream CLI owns ACP framing, protocol versions, capabilities, tools, permissions, terminal integration and SDK persistence. `internal/acp/adapter.mjs` decorates the public `ClaudeAcpAgent` configuration lifecycle, then imports the actual CLI with its original stdio. Do not add an ACP parser, capability filter, permission MCP bridge, or alternate built-in ACP implementation. `internal/claude/agent.go` prepares provider runtimes and documented `_meta.claudeCode.options.{settings,env}` without locating a separate Claude CLI or writing temporary settings files; the upstream SDK supplies Claude. Client metadata, MCP servers, hooks and non-routing preferences are preserved.

Each ACP session holds a reference-counted provider generation. `ccl use --acp <name>` pins `acp_provider`; empty follows `active_provider` (`EffectiveACPProvider`), and `--follow` unpins. Both selectors refer to the same `providers` map; `ccl ls` shows them in `USED BY`. Before an idle turn, the wrapper checks the full provider snapshot and calls upstream `resumeSession` to refresh changed configuration without replaying history; changed model defaults use upstream `setSessionConfigOption`. Both upstream v1 and v2 use the decorated `startTurn` boundary. Running and queued turns retain their generation. Retired runtimes close after the final lease, and successful runtime preparation outlives the configuration HTTP request. A private, token-authenticated loopback HTTP service carries only configuration and lease operations; its credentials are removed before loading upstream code. ACP stdout is untouched; stderr credentials are redacted. Session ids and transcripts belong to upstream. Adapter lookup: `--adapter` / `CCL_ACP_ADAPTER`, then the `ccl acp install` prefix `~/.ccl/acp-adapter` (pinned version, records its `node` path for GUI clients), then `claude-agent-acp` on PATH; Node.js must be >=22. `ccl acp` never installs anything itself (stdio belongs to the ACP client). `ccl bypass` does not apply to ACP.

Verify wrapper contracts with `node --test scripts/acp-adapter.test.mjs`. Real-adapter tests in `integration/acp` require `CCL_TEST_BINARY` and `CCL_TEST_AGENT_ACP`, use isolated HOME / USERPROFILE / CLAUDE_CONFIG_DIR and local fake providers, and run on Linux/macOS/Windows in CI. Never test ACP against a real user profile or paid model.

`providersession.Session` is a **copy** of the persisted provider. `UseProxy` is true for OpenAI-compatible types, `modelsdev`, or any non-empty `OAuthProvider` (including AutoClaw). Direct Anthropic API-key providers skip the proxy; Claude Code talks upstream with `ANTHROPIC_API_KEY` or `ANTHROPIC_AUTH_TOKEN` (`anthropicAuth: bearer`).

Loopback runtimes bind `127.0.0.1` and a random per-session key that is never written back to config. Upstream OAuth secrets live in `~/.ccl/auth/*.json` (0600), bound by `oauthAccountCredential`.

`ccl proxy [-p name]` / `ccl proxy start [name]` runs a detached standalone runtime; `stop` / `status` manage it via a separately authenticated loopback control endpoint. `internal/proxymanager` serializes starts/stops and journals a field-level Claude user-settings overlay in `~/.ccl/proxy/state.json` before applying it. Shutdown or crash recovery restores only unchanged owned values. Native Anthropic gateways use the passthrough in this mode (`providersession.PrepareProxy`), preserving x-api-key vs bearer auth. `internal/claude/standalone_overlay.go` makes normal/ACP launches override the standalone settings. The `default` selector does not undo that overlay: it is Claude Code's configuration as it stands, so it uses the proxy's provider while one runs; `ccl proxy start` on `default` starts nothing and stops a running proxy. Never exercise proxy start/stop on a real home during tests.

### Protocol ownership (`internal/oauthproxy`)

Canonical notes: `internal/oauthproxy/doc.go`. Do not reintroduce an external provider process (no qodercli, no Codex CLI).

| Ingress | Runtime | Notes |
|---|---|---|
| Anthropic API key | none (direct) | Claude Code hits `/v1/messages`; `ccl set` still needs `/v1/models` to auto-detect |
| OpenAI Chat API key / Kimi / WorkBuddy | `openai_chat_*.go` | Messages ↔ Chat Completions |
| Codex Responses API key / GPT OAuth | `codex_responses_*.go` + `internal/codexidentity` | All `openai_responses` gateways get CCL-owned Codex identity (`Originator: codex_cli_rs`, UA, `stream=true`, `store=false`). Protocol is `type`, not guessed from `/codex` in the URL |
| Grok OAuth | `xai_*.go` + `codex_responses_*.go` | cli-chat-proxy Responses; Grok Build identity headers; live `/models` catalog with 4.6/4.5 fallback |
| Gemini OAuth | `gemini_*.go` | Antigravity conversion |
| Zed | `zed_*.go` | zed.dev native-app login (RSA-encrypted loopback callback) → LLM token; per-model dispatch by catalog `provider` (anthropic→passthrough, open_ai→Responses, x_ai→Chat, google→`zedGeminiService`) behind an inner `zedGateway` that owns the `{provider,model,provider_request}` envelope; persisted `type` is only `openai_responses` for local dispatch |
| Kiro | `kiro_*.go` | Portal PKCE (default) or `--kiro-auth builder`; Amazon Q + EventStream |
| Qoder | `qoder_*.go` | Browser OAuth, COSY, WAF; `session_type=qodercli` is a wire field only |
| models.dev mixed | `mixed_runtime.go` + `anthropic_passthrough.go` | `ModelProtocols` map per model |
| AutoClaw / ZCode | `autoclaw_*.go` | CCL-owned Anthropic-to-OpenAI Chat adapter to `{origin}/autoclaw-proxy/proxy/autoclaw`; `ccl oauth autoclaw` runs the Google browser login (importing the encrypted desktop `auth.json` is optional), refreshes the session, and sends desktop-compatible managed-proxy headers without starting AutoClaw |

Shared 429/5xx fast retry is `retry.go` (500ms + 1s, then relay status/body/`Retry-After` untouched). Per-backend 401 refresh happens **inside** one attempt. Kiro has its own 1/2/4s loop; WorkBuddy/Zed inner gateways must not wrap the outer retry (would 3×3).

`ccl set` Auto Configure only GETs `/models` metadata for generic gateways. OAuth subscriptions have no Auto Configure row at all: `configureOAuthRuntime` copies the catalog straight from the loopback runtime (`runtime.Models()`), so a subscription is never probed as a generic endpoint. Per-slot `[1m]` markers live in `live().oneMSlots`; a slot that kept its model keeps its marker, so re-detection cannot re-open a window the user closed.

### Config, launch, TUI

- `internal/config`: `~/.ccl/config.yaml`. `Load` is read-only and normalizes in memory; every write goes through `config.Update(fn)` (file lock, re-read, apply, atomic 0600 write) — cmd code uses `updateProvider` / `replaceProvider`. There are no config migrations: old formats are not read. An OAuth provider's `type` is derived (`provider.EffectiveType`), not persisted; context sizing is the typed `contextPreset` field.
- Global fields: `active_provider`, `acp_provider` (both are name selectors into one `providers` map; empty `acp_provider` follows `active_provider`), the reserved selector `default` (`provider.DefaultProvider`, never a `providers` key) for Claude Code's own configuration — plain `claude` with the environment unchanged for normal mode, `claude.DefaultAgentLaunch` (no settings, routing env restored to ccl's own) for ACP; a fresh install selects it, `lang`, `bypass_mode` (not `auto_mode`), `sign_on` (`off` default; ccl writes Claude Code's empty `attribution`, so commits have no Co-Authored-By trailer; `ccl sign --default` also edits `~/.claude/settings.json`), `log_level` (`off` default; `ccl log`). With no provider selected ccl errors; it never builds one from shell `OPENAI_API_KEY` / `ANTHROPIC_*`.
- `internal/claude`: `--settings` outranks the user's own settings, so `outputStyle: Concise`, `language` (from `ccl lang`), `statusLine` (`ccl statusline`; per-provider `statuslineDisabled` opts out) and `modelPicker` (provider slots + pool) are written only when the user's `$CLAUDE_CONFIG_DIR/settings.json` or the project's `.claude/settings{,.local}.json` does not define that key (`user_settings.go`). `effortLevel` / `ultracode` come from `ccl provider effort|ultracode`; `CLAUDE_CODE_EFFORT_LEVEL` is never exported (it pins `/effort`), and `fastMode` is omitted unless on (writing `false` would undo `/fast`). Proxy sessions default `CLAUDE_CODE_ATTRIBUTION_HEADER=0` and `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`; Fast is sent as `X-Ccl-Fast-Mode` via `ANTHROPIC_CUSTOM_HEADERS`, and runtimes strip the hint headers before forwarding. `inheritedEnvToDrop` removes shell `CLAUDE_CODE_USE_*`, model vars, nested-session markers, and the unused credential/custom-header var. Context presets Default / Balanced 500K / 800K are also exported as env because Claude Code has ignored settings-only auto-compact. Provider `Env` overrides defaults except proxy transport keys. Settings files live in `~/.ccl/run` (PID-named, stale ones swept).
- TUI (`cmd/advanced_config*.go` — state, `_view`, `_input`, `_results`, `_async`, `_connection`; `github.com/grindlemire/go-tui`): components implement `Render` / `KeyMap` / `HandleMouse` / `Watchers`; use `tui.WithDisplay(tui.DisplayFlex)`. Single-page set wizard.

### Browser UI (`ccl web`)

`ccl web` serves conversations over HTTP + SSE from `internal/webui`. The page is a React + TypeScript + Tailwind app in `internal/webui/frontend` (Vite); `npm run build` writes `internal/webui/web`, which is embedded with `go:embed` and **committed**, because `go install` (and `ccl update --method go`) must build without Node. After changing the frontend, run `npm test && npm run build` there and commit `internal/webui/web` with it; CI's Web UI job fails when the committed build is stale. For live work, run `ccl web --no-open` and `npm run dev` (Vite on `localhost:5173`, proxying `/api` and `/health` to `CCL_WEB_URL`, default `http://127.0.0.1:8099`). Event-to-message logic lives in the pure `src/thread.ts` (vitest). Replies render through react-markdown without raw HTML. `go.mod` ignores `node_modules`. One conversation is one ccl terminal session: every turn is a separate Claude Code process (`--print --verbose --input-format stream-json --output-format stream-json --include-partial-messages --permission-mode <mode>`, plus `--permission-prompt-tool stdio` unless the mode is `bypassPermissions`) that continues the previous one with `--resume <claudeSessionId>` from the first `system/init` event, so provider/model/effort apply at turn boundaries and cancel means killing the process. Provider switching only changes conversation metadata and always launches through `claude.PrepareContext` + `Launch.Command`; `ccl web` never writes `~/.ccl/config.yaml` to switch providers, and `default` follows the same path as a plain `claude` launch. History is `~/.ccl/web/sessions/<id>/{meta.json,events.jsonl}`; every event carries an increasing `seq`, so a reconnecting stream asks for `?since=` (an EventSource reconnect sends `Last-Event-ID`). Every turn ends with exactly one `result` event — Claude Code's own, or one the runner writes when the process reported none (`cancelled: true` for a user stop) — because the browser treats it as the end of the turn. A result's `usage.costUsd` is Claude Code's running total for the session (it continues across `--resume`), so never sum it: the runner stores the difference as `turnUsage` and keeps the last total in `meta.claudeCostUsd`. A turn waiting for a `--max-concurrency` slot returns at once and launches in the background. The process may still be exiting after its `result`, so a non-GET session request (other than cancel and permission answers) first waits up to 15s for a turn whose result is stored (`Timeline.Settle`) instead of answering 409; a turn still working stays busy. `meta.pinned` / `meta.archived` only change where the page lists a conversation: `PATCH` with just those uses `RelabelMeta`, which keeps `updatedAt`, and needs no idle turn (route fields still do). The sidebar groups the active project's conversations (pinned, then by day, archived folded away), its search covers every project, and the project page selects several conversations to archive or delete. A result on a subscription provider (non-empty `oauthProvider`; `default` is not one) carries `subscription: true` (`LaunchSpec.Subscription`), and the page then shows tokens without Claude Code's cost estimate. Each project's defaults for new conversations (provider, model, effort, permission mode) live in `<store>/projects.json` (`projects.go`): `GET /api/workspaces` lists them as `defaults`, `PUT /api/workspaces/<id>/defaults` sets them, and `POST /api/sessions` fills what the request leaves empty from them (a provider deleted since is skipped with its model); the composer edits a new conversation's route before its first message. `POST /api/sessions/:id/share` gives a conversation a random 64-hex `shareToken`; `/share/<token>` serves the page, which reads the public `GET /api/share/<token>` (title, folder name only, events, worktree diff) and `…/uploads/<file>`, all with `Referrer-Policy: no-referrer`; `DELETE …/share` revokes it. `GET /api/sessions/:id/worktree/diff` is the worktree's diff from its merge base with the base branch (uncommitted tracked changes included, 2 MB cap), which Markdown/HTML exports append. Session responses carry `running` from memory; it is never written to `meta.json`. Attachments upload to `POST /api/sessions/:id/uploads` and live in the session's `uploads/` (the id is a random prefix plus the sanitized name; the type comes from the bytes, never the extension). Every turn writes one stream-json user message on stdin and keeps stdin open until its `result`, then closes it so the process exits: attached png/jpeg/gif/webp up to 5 MB go as base64 image blocks, every other file by path in the text. Permission questions arrive as `control_request` / `can_use_tool` on stdout; they become `permission` events (input redacted, the original kept in memory for the answer) and `POST /api/sessions/:id/permissions` writes the `control_response` (allow with the original `updatedInput` — plus `answers` for AskUserQuestion — or deny with a message; "remember" reuses Claude Code's suggestions with `destination` forced to `session`; plan approval adds `setMode` and stores the mode on the session). Other control requests get an error response so Claude Code never waits. A session's `permissionMode` defaults to `bypassPermissions` when ccl's `bypass_mode` is on, else `default`. `GET …/uploads/:file` serves only those image types inline (everything else, SVG included, downloads) under `Content-Security-Policy: sandbox`. Init events carry `slashCommands` and `mcpServers`; `message_start` usage becomes `context` events (the context ring); unstreamed (sub-agent) assistant text is emitted from the complete message, and sub-agent events carry `parent`, the Task call they belong to; `GET /api/capabilities` returns the latest ones for the composer menus. The page follows `ccl lang` (else the browser language) through `src/i18n.ts`; its layout follows claude.ai/code without its fonts or marks. Workspace tools: `/api/files/*` (list, read, write with an `expectedHash` optimistic lock, search, uploads that never overwrite, raw with `?token=`) resolves every path through `resolve` (symlinks evaluated against the workspace's real path); `/api/git/*` runs git from argv with `GIT_OPTIONAL_LOCKS=0`, paths after `--`, branch names through `check-ref-format`, commit messages on stdin. `/api/claude-sessions` lists Claude Code's own transcripts for the workspace (`~/.claude/projects/<cwd with non-alphanumerics as ->`) and imports one as a conversation that resumes it. Scheduled messages persist in `<store>/schedules.json` and go out through the same `startTurn` as `/messages`. `/api/oauth/login` runs `ccl oauth <name> --no-browser` (the server's own binary) and relays the URL it prints; `/api/mcp` reads Claude Code's MCP configs (never returning env or header values) and changes them only through `claude mcp add-json/remove`. The web terminal (`/api/terminal`, creack/pty, SSE output from a byte offset, POST input) is on by default (`--no-shell` turns it off) and unavailable on Windows.

The settings dialog (`SettingsDialog.tsx`; providers are created and edited in a dialog of their own) writes `~/.ccl/config.yaml` through `config.Update(fn)` for every change — never hand-built YAML; a subscription login started from the page writes through `ccl oauth` itself. `GET /api/config` masks API keys to the last four characters; `PATCH /api/config/providers/:name` treats `apiKey: ""` as "leave it", `null` as "clear it", and any other value as a replacement. `default` is reserved: 403 on edits and deletes. Deleting the active or ACP provider is 409. A running turn keeps the provider snapshot it was started with, so settings changes only affect new turns. `/health` is public; every `/api` route needs `Authorization: Bearer <token>`, while the SSE and events endpoints also accept `?token=` because EventSource cannot set a header. A loopback bind (`--host 127.0.0.1`, the default) requires no token; any other host refuses to start without `--token` or `CCL_WEB_TOKEN`. The browser opens once the listener is ready unless `--no-open`. Ctrl+C / SIGTERM cancels the `BaseContext` (open SSE and terminal streams end at once), then `Server.Close` stops schedules, logins, terminals and turns in flight (stored as cancelled) within 3s; a second Ctrl+C exits immediately. Workspaces (`workspaces.go`) are each repeatable `--workspace` (default `.`), every non-hidden directory directly inside a `--workspace-root` (rescanned every 5s), and folders the page added — "open another folder" / "new project" through `POST /api/workspaces {path}` and `GET`/`POST /api/directories` (a folder browser that lists directories only and creates one single-segment folder), persisted in `<store>/workspaces.json`; `--lock-workspaces` refuses both with 403. The page calls workspaces projects (code, API and flags keep `workspace`): the Projects page (`ProjectsPage.tsx`) lists them, and a project's page edits its `CLAUDE.md` (the root one, else `.claude/CLAUDE.md`) and `CLAUDE.local.md` through `/api/files` with the `expectedHash` lock (a 409 offers a reload); unsaved edits ask before the page is left. It also edits `permissions.allow/ask/deny` in `.claude/settings.json` / `settings.local.json` (each change saved at once, other keys kept) and links to the project's MCP connectors. The settings dialog's Instructions tab edits the user `CLAUDE.md` in `$CLAUDE_CONFIG_DIR` (default `~/.claude`) through `GET`/`PUT /api/memory` (`memory.go`; the same hash check via `saveVerified`), the only file outside a workspace the page can write. A new conversation in a git repository may run in a worktree (`worktree.go`): `POST /api/sessions {worktree: true}` runs `git worktree add -b ccl/<first 8 of the session id>` at the project's HEAD under `<store>/.worktrees/<workspace id>/<name>` (outside the project, so its status stays clean; `CLAUDE.local.md` and `.claude/settings.local.json` are copied in), and `meta.worktree` records name, branch, base branch and commit. Turns run there; files/git/terminal/MCP requests add `&worktree=<name>` (validated, resolved under the store only). `GET /api/sessions/:id/worktree` reports ahead/behind/dirty and changed files; `POST …/worktree/merge` runs `git merge --no-ff` in the project only when it has the base checked out, both sides are clean and there are commits (a conflicted merge is aborted); `POST …/worktree/push` pushes with `--set-upstream` to the base's remote (else `origin`). Deleting the conversation removes the worktree (uncommitted changes are 409 unless `?force=1`) and the branch only when merged (`git branch -d`); a turn whose worktree vanished is 409 (`ErrWorktreeMissing`). Requests name a workspace by id (the first 12 hex of sha256 of the real path) — `POST /api/sessions` takes `workspace: <id>` and a path is 400; files/git/claude-sessions/mcp/terminal requests carry `?workspace=<id>` (none means the first; an unknown id is 404). A conversation runs only in the workspace it recorded; when that is no longer served, `/messages` is 409 (`ErrWorkspaceNotServed`). Prompts travel in the stdin message, never through a shell. Without a token, `guard` (guard.go) accepts only loopback `Host` headers (DNS rebinding) and refuses state-changing requests from another site's `Origin`; every JSON write must say `Content-Type: application/json`, and multipart is accepted only on `/uploads` routes.

### i18n layering

User-facing Chinese lives in `cmd/` via `locale.T`. `internal/` must not contain Chinese string literals (`internal/protocol/no_chinese_strings_test.go`); `internal/locale` is the exception.

### Cloud sync

`internal/cloudsync` encrypts `config.yaml` + `auth/*.json` to iCloud / Google Drive under `ccl cloud ...` only (registry v2 in `~/.ccl/cloud`; no v1 layout, passphrase, Keychain, recovery-key or pairing modes). The Desktop OAuth client (Cloud project `93551281893`) is not in source: release ldflags inject `cloudsync.googleOAuthClientID/Secret`; PKCE is the real auth boundary; `appDataFolder` belongs to the Cloud project. The random profile key is stored in the cloud `profile.json` (`account_key`), so `loginFirstRemote` on a new device opens the account's profile (or creates one) with nothing but a login. `--no-browser` (default when `headlessHost()`: SSH, Cloud Shell, Linux without a display) prints the authorization URL and reads the redirected `127.0.0.1` address pasted back (`cloudsync.WithPastedRedirect`), still with the Desktop client + PKCE. Do not reintroduce the OAuth device flow: Google rejects `drive.appdata` there (`invalid_scope`) despite its docs, and `appDataFolder` is per Cloud project, so any other client would see different data.

## Product facts that affect code changes

ccl is a launcher + protocol proxy, not a fork of Claude Code. Extra CLI args after a non-ccl command are passed through.

OAuth public names: `gpt` `gemini` `grok` `qoder` `kimi` `kiro` `workbuddy` `workbuddycn` `autoclaw` `zed`. `workbuddy` is www.workbuddy.ai and `workbuddycn` is www.workbuddy.cn: same plugin API and chat protocol, different origin and credential `type` (see `workbuddyDeployment`). Slot defaults: `internal/provider/oauth_defaults.go` (empty slots only; missing catalog entries are cleared at launch).

`bypass` injects `--dangerously-skip-permissions`, except when `--permission-mode` is given or the first arg is a Claude Code subcommand. Provider management lives under `ccl provider` and sync under `ccl cloud`; there are no root shortcuts for them. `ccl doctor` is read-only and bills nothing without `--probe`. `ccl update` verifies the `.gz` asset against `SHA256SUMS`; `--method self|npm|go` is required off a TTY.
