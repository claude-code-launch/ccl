# Development architecture and subsystem contracts

Read the relevant section before changing a subsystem. This reference preserves the detailed contracts formerly embedded in the root agent instructions.

## High-Level Architecture

Detached Codex services are reused only when their protocol version matches the starting binary. Version 16 adds immutable route/runtime generations, multi-provider bindings and account-bound Gemini discovery. Starting a new binary replaces an older protocol on the existing loopback port. Binary upgrades, shared/independent changes and local/remote catalog source changes still replace the daemon; ordinary provider/configuration reloads do not.

The daemon polls configuration and the models.dev cache stamp once per second. It reads only its explicitly bound primary and `--with-provider` names, never follows `active_provider`. Context/effort metadata is published without replacing runtimes. Model pool, endpoint, credential or protocol changes prepare a complete new set of provider runtimes and an immutable catalog/route snapshot, persist the catalog and recovery journal, then publish the snapshot atomically. A request leases one snapshot through the end of its response body, including SSE; retired runtimes close after their final lease. Histories, listener, local token and catalog path survive. Failed preparation/discovery/persistence retains the last usable registry. An independent-mode default whose route was removed moves only if the TOML value is still CCL-owned; `PreviousApplied` lets crash recovery recognize both sides of that journal-before-config update. User-edited selections remain untouched.

`ccl codex start NAME --with-provider OTHER` explicitly adds account-bound providers to one gateway; repeat the flag for more. `--with-provider ''` clears additional bindings. Subsequent starts/menu switches inherit additional names unless supplied. Each `ccl/<provider>/<model>` alias binds to exactly one runtime; same-model names across providers never share credentials. `ccl codex start --refresh` requests rediscovery and runtime replacement through the authenticated control channel, without changing its URL/token. Gemini inventories also refresh every five minutes; a failed refresh leaves the running inventory in place. A missing bound provider is an error, not permission to select another account.

`GET /v1/models` and `/v1/codex/models` serve the current merged native+CCL catalog in shared mode, or only CCL in independent mode. ETags include the catalog content and `client_version`; responses are private/revalidated, vary by authorization/account header and are bounded to 1 MiB. The merged catalog never supplies the inference allow-list. Shared mode keeps the journaled local JSON: current Codex restricts `[model_providers.openai].model_catalog_url` to HTTPS on allowed ChatGPT hosts, so a loopback URL there is invalid. Independent mode can opt into `--catalog remote`; its owned custom-provider table gets the loopback catalog URL, while effective root/default-profile `model_catalog_json` values are reversibly removed. The JSON file remains updated for `--catalog local` fallback. Explicitly disabled `features.api_key_model_discovery` is reported, never silently changed. Returning to `--shared` defaults back to the local source.

`CatalogMode` (`local` / `remote`) selects the transport only. `CatalogCapabilities.SupportsRemoteFetch` describes the configured remote-fetch path; `SupportsLiveReload` means a qualified immediate Desktop-picker reload guarantee and remains false in all current configurations. This does **not** claim that Codex cannot refresh models in the background. No mode is marked live merely because it uses a URL. The CLI/status and provider/mapping-save feedback distinguish CCL route/catalog changes from client selection: “Model configuration saved. CCL will update routes and catalog automatically; Codex may need a restart to refresh the model list.” Save feedback is shown only for an explicitly bound, running Codex provider.

Qualification on bundled **Codex `0.166.0-alpha.6`**, using one isolated app-server process, fake credentials and a local metadata-only endpoint (no inference):

1. Generated `ModelListParams` contains only `cursor`, `includeHidden` and `limit`; there is no public force-refresh argument. The corresponding handler uses `OnlineIfUncached`, so the initial A → upstream B → repeated `model/list` sequence returns A with one fetch. This establishes warm-cache reuse, not permanent caching.
2. Generated public server notifications include model rerouting/verification/safety and provider auth recovery, but no catalog-update notification. Internal model-manager watch channels exist; their existence does not establish Desktop delivery or picker behavior.
3. During a **306-second idle interval with no RPC calls**, the endpoint received one additional request; the next `model/list` in the same process returned the changed model. The matching version's source has a **270-second Online background refresh worker** and a separate **300-second cache TTL**. The observed idle fetch confirms background refresh; it should not be described as every-call refresh or attributed solely to TTL expiration. Cache-aware reads can also fetch when no valid cache remains.
4. Changing `model_providers.fixture.model_catalog_url` through `config/batchWrite` with `reloadUserConfig=true` did not immediately invalidate this process's retained catalog or fetch the new URL. That covers this provider URL mutation only; account/auth changes have separate invalidation paths, and other mutations are not ruled out.

Reproduce with `CCL_TEST_CODEX=/absolute/path/to/codex python3 integration/modelpicker/catalog_refresh.py`; use `--idle-seconds 0` for the short cache/configuration cases. The script generates the actual client schemas, records request timestamps and public notification names, rejects inference, and confines its profile to a temporary directory. Do not turn an app-server background refresh observation into a Desktop picker guarantee. A client restart remains the fallback when its picker is stale. `ccl` launches Anthropic's Claude Code CLI against other model sources. Claude Code always speaks Anthropic Messages; ccl either points it at a real Anthropic-compatible gateway or starts a **127.0.0.1** loopback runtime that translates.

Data flow:

`main.go` → `cmd/` (Cobra + TUI) → `internal/config` + `internal/provider` → `internal/providersession.Prepare` → `internal/claude` (temp `settings.json`, env cleanup, `claude --settings ...`) → `internal/oauthproxy` when a proxy is required.

`ccl acp` wraps **`@agentclientprotocol/claude-agent-acp`** (Node.js >=22; CI pins 0.90.0). The upstream CLI owns ACP framing, protocol versions, capabilities, tools, permissions, terminal integration and SDK persistence. `internal/acp/adapter.mjs` decorates the public `ClaudeAcpAgent` configuration lifecycle, then imports the actual CLI with its original stdio. Do not add an ACP parser, capability filter, permission MCP bridge, or alternate built-in ACP implementation. `internal/claude/agent.go` prepares provider runtimes and documented `_meta.claudeCode.options.{settings,env}` without locating a separate Claude CLI or writing temporary settings files; the upstream SDK supplies Claude. Client metadata, MCP servers, hooks and non-routing preferences are preserved.

Each ACP session holds a reference-counted provider generation. `ccl use --acp <name>` pins `acp_provider`; empty follows `active_provider` (`EffectiveACPProvider`), and `--follow` unpins. Both selectors refer to the same `providers` map; `ccl ls` shows them in `USED BY`. Before an idle turn, the wrapper checks the full provider snapshot and calls upstream `resumeSession` to refresh changed configuration without replaying history; changed model defaults use upstream `setSessionConfigOption`. Both upstream v1 and v2 use the decorated `startTurn` boundary. Running and queued turns retain their generation. Retired runtimes close after the final lease, and successful runtime preparation outlives the configuration HTTP request. A private, token-authenticated loopback HTTP service carries only configuration and lease operations; its credentials are removed before loading upstream code. ACP stdout is untouched; stderr credentials are redacted. Session ids and transcripts belong to upstream. Adapter lookup: `--adapter` / `CCL_ACP_ADAPTER`, then the `ccl acp install` prefix `~/.ccl/acp-adapter` (pinned version, records its `node` path for GUI clients), then `claude-agent-acp` on PATH; Node.js must be >=22. `ccl acp` never installs anything itself (stdio belongs to the ACP client). `ccl bypass` does not apply to ACP.

Verify wrapper contracts with `node --test scripts/acp-adapter.test.mjs`. Real-adapter tests in `integration/acp` require `CCL_TEST_BINARY` and `CCL_TEST_AGENT_ACP`, use isolated HOME / USERPROFILE / CLAUDE_CONFIG_DIR and local fake providers, and run on Linux/macOS/Windows in CI. Never test ACP against a real user profile or paid model.

`providersession.Session` is a **copy** of the persisted provider. `UseProxy` is true for OpenAI-compatible types, `modelsdev`, or any non-empty `OAuthProvider` (including AutoClaw). Direct Anthropic API-key providers skip the proxy; Claude Code talks upstream with `ANTHROPIC_API_KEY` or `ANTHROPIC_AUTH_TOKEN` (`anthropicAuth: bearer`).

Loopback runtimes bind `127.0.0.1` and a random per-session key that is never written back to config. Upstream OAuth secrets live in `~/.ccl/auth/*.json` (0600), bound by `oauthAccountCredential`.

`ccl oauth claude [alias]` creates a normal `oauthProvider: claude` provider bound by `oauthAccountCredential` to an opaque local profile id under `~/.ccl/claude-accounts/profiles`. Claude owns OAuth, Keychain and token refresh. `ccl ls`, `ccl use NAME`, and one-shot `ccl --provider NAME` select all provider types; there is no separate account flag or selector. `default_claude_provider` points `default` at the last successful Claude login; `ccl use NAME --default` overrides it, while `ccl use default --default` clears it to restore the original Claude environment. Renames update the default reference; a removed default is an error rather than a silent identity switch. Native profiles support terminal, ACP and web launches without a proxy. Native account selection is local and never launches authentication. Account model/effort/env preferences belong to Claude itself; CCL provider-only option setters reject these accounts instead of silently ignoring writes. `internal/claudeaccount` checks native, project, managed and extra CLI settings for conflicting authentication before login/terminal/web/ACP launches; diagnostics contain source paths and keys, never values. ACP binds its initial profile and asks for a restart across profile changes because upstream persistence is process-wide. Profile directories and credentials are local and not cloud-synced. The previous standalone account registry is imported once from cmd into normal providers without moving credentials; a local marker prevents reimport after renaming or deletion.

`ccl codex [-p name]` / `ccl codex start [name]` runs a detached **Codex-only** runtime; the removed `ccl proxy` entry is not an alias and is rejected before Claude Code dispatch. Runtime state remains in the existing proxy directory so active daemons and recovery journals remain manageable; `stop` / `status` manage it via a separately authenticated loopback control endpoint. `internal/proxymanager` journals the Codex overlay in `~/.ccl/proxy/state.json` before applying it. A Codex profile must already exist; open Codex once first. New daemons never resolve Claude launcher models, generate Claude settings, inspect `CLAUDE_CONFIG_DIR`, or modify Claude configuration. They prepare `providersession.PrepareProxy` directly; its internal Messages endpoint remains the shared protocol adapter for converted Codex models, including native Anthropic gateways with x-api-key/bearer auth. The public proxy endpoint is Codex Responses. `default` stops a running Codex proxy and restores the original Codex configuration. Ordinary `ccl`, ACP and browser Claude launches remain independent. Old shared-proxy journal fields survive only for one-time restoration during upgrade, stop or crash recovery, retaining later user edits; `internal/claude/standalone_overlay.go` is legacy protection while such an old journal still exists. Never exercise proxy start/stop on a real home during tests. `internal/codex` wraps the same runtime for Codex Responses: native Responses backends pass through; other backends convert via Messages and return Responses SSE. The separate CCL model allow-list never comes from the merged picker catalog; native requests retain their original OpenAI/ChatGPT route, while CCL requests receive only the runtime credential. Existing Codex catalogs/cache or installed bundled metadata supply native entries. In shared mode a journaled TOML overlay changes only `openai_base_url` and `model_catalog_json`, preserving comments, native login/provider and later user edits. CCL does not rely on an in-process reload of the local JSON catalog. Picker labels normally omit provider names; identical labels across attached providers add the provider name, and native-name collisions get a short CCL marker; WorkBuddy internal revisions sharing a name collapse to their formal model ID while all old routes remain valid. Explicit reasoning metadata supplies picker effort controls and converted Messages requests must enable thinking as well as carry effort. The local models.dev metadata cache supplies effort controls for recognized converted models. When a runtime publishes no reasoning levels at all, unknown models retain GPT's compatibility ladder (low, medium, high, xhigh, max, ultra, default low); known empty effort lists are never filled. A catalog already advertising levels keeps unknown models as published. Gemini maps thinking levels above high to high. CCL catalogs set `node_repl_disabled` false so Codex attaches its local Node REPL; computer use and browser control call that tool and execute on the client. macOS has an AppKit menu bar helper using the built-in JXA interpreter (no cgo/Swift build dependency); it monitors authenticated control readiness and offers provider switching plus stop. Menu names are loaded afresh without credentials; a successful switch updates active_provider and does not quit or reopen Codex, because immediate Desktop picker reload has not been qualified and a client restart remains the fallback. A failed replacement restores the previous provider before showing an error. Command-line start/switch/stop likewise leaves the client running. Provider switches use live runtime generations on the existing daemon; mode/source changes use journaled replacement. `CCL_PROXY_NO_MENUBAR=1` disables it for isolated tests/headless use. Real Codex tests in `integration/codex` require `CCL_TEST_BINARY` and `CCL_TEST_CODEX`, use fake credentials/local providers and exercise a real local tool round trip.

`ccl codex start --independent` opts into the official custom-provider path. The owned `model_providers.ccl_proxy` table uses Responses, `requires_openai_auth=false`, disabled WebSockets and a per-session loopback bearer token. The picker contains only the CCL allow-list; ordinary native/unknown model requests are rejected. The app-server account/read response is account=null / requiresOpenaiAuth=false even when a ChatGPT login is cached, so this mode does not depend on that account's quota. Do not fabricate quota responses or alter the desktop app. Restart Codex to load provider/auth/catalog changes. `--shared` restores the native OpenAI provider with the merged picker. With neither flag, starts/menu switches inherit the running mode; without a runtime journal (including after stop), startup defaults to shared. Codex 0.166+ resumes chats with their persisted model provider: independent chats bind to ccl_proxy, shared chats to openai. Removing the owned ccl_proxy block on stop/shared mode therefore makes independent chats unavailable until independent mode is restored. Cross-provider continuation requires a fork under the new provider; do not rewrite persisted chat records or claim that all chats resume across modes. See https://learn.chatgpt.com/docs/codex-sdk#resume-a-thread-without-loading-its-history. Mode changes retain the listener port. Root and active legacy-profile model/provider/catalog overrides are journaled; unrelated profile settings remain intact. A pre-existing ccl_proxy table is a collision, not an invitation to overwrite it. Stop removes the exact owned provider block; a user-edited block survives and must be renamed before reuse. Native login files and upstream account credentials are never copied into the custom provider.

Replacing a daemon for an upgrade or client mode/catalog-source change reuses the previous Codex listener port for the same Codex home. Already-open clients cache the endpoint and can retry on that address after the brief restart; generating a new random port strands both native and CCL requests. The internal replacement address accepts only an explicit `127.0.0.1` port and a bind failure must not silently pick a different port. Gateway close explicitly releases the listener even if its Serve goroutine has not registered it yet, so immediate replacement can bind synchronously. This preserves connectivity. Model/tool picker and transport settings can still require a client restart; CCL does not promise immediate Desktop refresh. Isolated process tests keep using the original URL across all three replacement paths and verify native credential separation.

Converted Codex requests with no explicit output budget use the runtime model's advertised `MaxOutputTokens`, or 32768 when unavailable; the former 4096 fallback prematurely exhausted long reasoning. Explicit client budgets remain supplied to the converter. Budget-based thinking leaves answer room within a known model capacity. Actual upstream token exhaustion still emits `response.incomplete` / `max_output_tokens`, never a fabricated completed response. Native Responses routes pass through unchanged.

Converted Codex models advertise `supports_search_tool`. `internal/codex/convert.go` translates client-executed `tool_search` into an ordinary function tool and `internal/codex/stream.go` translates its response back into `tool_search_call`. Codex searches its local tool catalog and returns `tool_search_output`; the adapter replays that result and loads only the selected definitions, preserving namespace and custom-tool formats. Deferred definitions stay unloaded when client search is available. CCL owns no search index or discovery loop, and only Codex executes actual tools under its normal permissions. Discovered definitions come from the current request/history, never other sessions/accounts. Native Responses routes remain passthrough and do not gain an adapter capability declaration. Real-client tests use fake upstreams and cover search, tool execution and permission denial; reliable use by a particular upstream model still needs model testing. Synthetic request-byte reductions are not measured production token savings.

Cross-model history is normalized only at the backend boundary. Before native Responses forwarding, `history_interop.go` removes unencrypted reasoning from stateless requests (including legacy CCL IDs) and turns CCL compaction summaries into ordinary user history. Native encrypted reasoning remains unchanged; translated backends skip opaque native reasoning while retaining messages and tool results. Native encrypted compaction cannot be decoded locally. Translated backends may recover a bounded excerpt of the matching local chat transcript as described below; missing or mismatched history is rejected. Keep native routing, credentials and `store` unchanged. Real-client tests resume one conversation CCL → native → CCL without model calls outside local fixtures.

`context_migration.go` handles opaque native compaction only on converted routes. A UUID chat ID from Codex client metadata/headers, matching session metadata and the exact compaction ciphertext must identify the same local rollout checkpoint; a supplied account header must also match. Only files for that ID under CODEX_HOME sessions/archived_sessions are considered, with symlinks confined to the Codex home. Fork/base history from another chat, missing base records, mismatches and missing transcripts fail explicitly. No session files are rewritten and no credentials or reasoning traces are recovered. The adapter reads visible user/assistant/tool text up to the matched checkpoint, keeping a bounded beginning/recent excerpt (16K/48K bytes, individual records excerpted at 4K, at most 32 files / 128MiB). This is not decryption or lossless semantic summarization. Images and older/lengthy details may be missing; a visible CCL migration notice accompanies the subsequent answer. Cached excerpts/notices use bounded, owner/session-scoped memory and survive only the daemon lifetime. Native Responses traffic remains unchanged.

On a model downshift, Codex can compact using the previous native model name. In independent mode only a native entry from the source catalog may delegate that internal compaction to the configured CCL default route. Recognize explicit compact endpoints, compaction_trigger or client turn metadata request_kind=compaction with no tools; use the target model's own default effort. This does not add native names to the ordinary routing allow-list. The original client still owns the summarization request, normal model call, tool registry and permissions. Real-client tests cover shared → independent resume with native encrypted compaction, a fixed chat ID, retained visible goals and no opaque/undeclared-tool replay.

Translated history also follows the current tool declarations. When a model/tool-mode switch retires a tool, replay its past call and result as labeled history text, preserving image content; do not send an undeclared `tool_use` example or restore the retired capability. Desktop-delivered named tool outputs without `call_id` (including `codex_app.send_message_to_thread`) are notifications, not results of an invented model call. Nameless, uncorrelated outputs still fail validation. Provider calls outside the current registry remain rejected; errors include bounded tool names for diagnosis, never arguments. A real-client regression resumes a classic MCP conversation in code mode and checks that the previous result survives while JavaScript invokes the client MCP again.

The Codex tool harness also follows the installed native catalog. `Plan` calls `inheritClientToolMode`: when a genuine native entry advertises `tool_mode: code_mode_only`, translated CCL entries inherit that mode and its Node REPL review requirement. Stale CCL entries never supply the template; older catalogs and native Responses passthrough entries keep their existing mode. Node REPL enablement and image input alone do not select the desktop tool harness. The proxy still translates code-mode custom calls to ordinary function tools; JavaScript, MCP/computer tools and permission checks execute in the Codex client. A real-client regression checks that catalog inheritance enables the exec/wait harness and that JavaScript can invoke a local MCP fixture and return its result.

Image capability travels in `protocol.ModelInfo.InputModalities`, including Qoder `is_vl`, WorkBuddy `supportsImages`, and Responses/model-catalog modality fields. Only models that advertise images receive the Codex image modality; unknown models stay text-only. Keep `node_repl_disabled` false. Responses function/custom tool result arrays must become typed Messages content, preserving image data rather than JSON text. Qoder and Chat put tool screenshots in a user message after all tool replies, without duplicating base64 as tool text. Real-client screenshot tests check the image gate and image round trip; they do not prove a model can reliably operate a desktop.

### Protocol ownership (`internal/oauthproxy`)

Canonical notes: `internal/oauthproxy/doc.go`. Do not reintroduce an external provider process (no qodercli, no Codex CLI).

Converted Codex requests explain the mapping from logical names in client instructions to the current flattened function declarations, including the JSON `input` wrapper for custom tools. Executor documentation and historical calls never authorize additional functions; the response bridge still rejects every undeclared name. Gemini 3/4 requests with compact function declarations (`<= 8` tools, such as Codex's `exec`/`wait`/`tool_search` set) use `VALIDATED` for implicit/explicit auto tool choice, allowing text answers while constraining generated calls to declared functions and schemas; larger Claude Code / MCP tool catalogs keep default `AUTO` mode unless explicitly requested so Antigravity's grammar compiler does not stall before streaming headers. Explicit none/required/specific-tool choices retain `NONE`/`ANY` and the sanitized allowed name. Tool-free requests and Antigravity's Claude route keep their existing modes. A terminal `MALFORMED_FUNCTION_CALL` remains a generation error, never successful completion, and partial streams are not retried or replayed.

Converted Codex tools keep short, valid unnamespaced names such as `exec`, `wait` and `tool_search`. Namespaced/unsafe/long names retain deterministic hash aliases, and root names already ending in the reserved 12-hex hash suffix are hashed too so they cannot impersonate those aliases. Chat conversion binds responses to the current tool declarations. Streamed function names are assembled from exact declaration prefixes, accepting repeated/cumulative complete names only when the interpretation is unique. Validate every name in a parallel batch before emitting its first call. Undeclared, incomplete, ambiguous or damaged names fail without exposing embedded reasoning/DSML as diagnostics; neither the parser nor Codex bridge guesses a replacement or executes embedded protocol text. This is a compatibility fix and validation boundary, not a guarantee that an upstream model will always generate a valid call. Generation failures are never silently retried after partial output.

Gemini conversion carries each unsigned Messages `tool_use.id` through `functionCall.id` and pairs the result's `functionResponse.id`, including histories replayed from Gemini to Antigravity's Claude models. Native response call IDs are retained; CCL generates a client ID only when the upstream omits one. Signed native parts remain byte-identical on Gemini routes: a request-scoped map pairs their original native ID (or its absence) with the persisted client tool ID, so even older synthetic IDs yield correctly correlated results. Streamed thinking chunks that close with a trailing `thoughtSignature` part keep the active thinking block open and embed the full accumulated thought text into the encoded `ccl-gemini-part-v1:` payload; when replaying onto Antigravity Claude models, Gemini `thoughtSignature` fields on `functionCall` or non-thought parts and empty-text thought parts are stripped or skipped so Vertex AI Anthropic never receives a `thinking` block with a missing `thinking` field. Consecutive `model` turns and tool-result/Claude `user` turns are merged, and on Antigravity Claude routes `thought`/`text`/`functionCall` and `functionResponse` parts are ordered and paired 1-to-1 so split or concurrent tool turns cannot trigger Vertex AI `tool_use`/`tool_result` 400 rejections. Enabled `thinkingConfig` payloads set `includeThoughts: true` so Antigravity streams thought chunks immediately rather than buffering response headers until reasoning finishes.

`ccl oauth gemini` uses Antigravity credentials, separate from Gemini CLI / Code Assist and API keys. Discovery reads `loadCodeAssist` from production with only the bound credential, then passes the account’s returned paid or current tier as `entitlement.userTier` to `fetchAvailableModels`. An unavailable lookup or rejected tier permits the original project-only request. Free, legacy and onboarding choices are not sent as entitlements, and tier metadata for a different project is ignored. Both metadata calls share one credential refresh on 401. Daily and production are tried for the catalog; generation prefers the base that returned the inventory and falls back to the secondary Antigravity base (`daily <-> prod`) on network/header timeouts, 429s and 5xx responses. The client-family/version User-Agent is platform-aware. A complete, bounded, nonempty inventory is validated before atomically saving exact wire IDs, output/context limits and declared input modalities under `~/.ccl/cache/gemini/<identity digest>.json` (0600). The digest binds credential basename, account/project, client identity and bases; credentials without email also bind the refresh identity. Tokens are never included in the catalog. Failed discovery uses only this account's last good cache, then its saved configured models, with the static compatibility list as the final fallback. A cached real inventory may seed a new session and is marked stale so it cannot downgrade a running registry. Guessed static/configured fallbacks never overwrite an existing saved pool; preparing a runtime does not write provider configuration.

Gemini `-minimal/-low/-medium/-high` wire rows are grouped into one family picker entry only when actually returned. Resolve a family plus effort to that account's exact wire ID; use the server-advertised default, otherwise medium, otherwise its lowest available tier. Explicit suffixed IDs retain their tier and their variant `DisplayName`. Readable display names (family or variant `DisplayName`, including `[1m]` suffixes) normalize to the bound catalog's canonical family or wire ID before conversion and routing, so Antigravity Claude schema sanitization and Gemini 3/4 `VALIDATED` tool-calling mode apply to display aliases as well. A selected variant uses a single matching thinking level, without a conflicting thinking budget. Unsupported tiers/model IDs fail rather than guessing another model. models.dev cannot replace these authoritative account tiers. The fallback contains documented Argon/Flash wire variants, not an invented `gemini-4-pro` entitlement. New empty Haiku slots prefer `gemini-3.8-flash`; existing explicit model choices remain, apart from the previously retired generated `gemini-3.1-pro-low` migration. Catalog visibility alone does not prove inference entitlement. Fixtures exercise discovery, source/account isolation, cache failure and real wire selection without paid model calls.

Shared 429/5xx fast retry is `retry.go` (at most 500ms + 1s; a longer `Retry-After` returns immediately for the client to honor). Qoder and WorkBuddy credential HTTP clients enforce same-origin redirects and scrub login query values from network errors; Qoder reads exactly its bound credential and rechecks type/disabled under the refresh lock. Per-backend 401 refresh happens **inside** one attempt. Kiro has its own 1/2/4s loop; WorkBuddy/Zed inner gateways must not wrap the outer retry (would 3×3).

Converted Codex models resolve effort controls from `~/.ccl/cache/modelsdev.json` via `internal/modelsdev.CachedIndex`; no model database is embedded in the binary. OAuth success and confirmed `ccl set` save refresh the public models.dev API with a five-second budget; `ccl set --refresh-models` refreshes metadata without opening the editor or changing providers. The models.dev provider picker uses the same network-first/offline-cache path. HTTP ETags avoid redownloading unchanged data. Validate a complete response before atomically replacing the last good snapshot; a separate hash-bound validator file cannot attach an ETag to mismatched JSON after a crash. Updates use a cross-process lock. Network/invalid-data failures fall back to a valid offline copy; without one, authentication/configuration still succeeds and Codex retains compatibility defaults. Models.dev metadata is never downloaded by proxies on startup or during inference. They lazily build one immutable index per unchanged local snapshot. The running daemon watches local cache/config stamps and refreshes catalog-only settings without replacing its runtime; The client may need a restart to refresh its picker. Explicit `codex start` handles binary/protocol upgrades on the same port; provider changes use the live registry.

Exact `modelsDevProvider` (or OAuth provider ID) entries take precedence, then canonical model-owner entries, then `opencode-go` / `opencode` reference rows, then unambiguous other rows. IDs and exact display names match without fuzzy version stripping. Conflicting equal-priority entries are not merged. This index supplies metadata only: a deprecated reference row can still describe a live upstream route, and it never creates routes. `reasoning_options` of type `effort` supplies tiers; thinking switches (`none` / `toggle`) and token budgets are not invented slider rungs. A known empty effort list prevents GPT compatibility defaults. Unknown models keep existing fallback behavior, and native Responses metadata stays on its own path. Keep an existing valid default; otherwise choose low if available, or the first tier. models.dev currently supplies no default effort. WorkBuddy's discovery still owns available IDs, labels, prices and images; its per-model reasoning detail is not consumed. `xhigh` and `max` survive Responses → adaptive Messages → Chat `reasoning_effort` conversion.

Qoder can return HTTP 200 with a stream-envelope `403 / 10605 / RESOURCE_LIMIT`, including `isQueued=false` and a positive `retryAfterSeconds`. Treat that metadata as a temporary resource limit, not an authentication failure. Qoder waits for actual model output before starting the Anthropic stream, so an early envelope rejection becomes HTTP 429 with `Retry-After`; the Codex bridge preserves both the header and error type. After partial output, emit a concise typed stream error without replaying the request. Do not add another provider retry loop or account fallback. Tests cover queued/nonqueued capacity, heartbeat frames, partial output, and ordinary permission denials separately.

`ccl set` Auto Configure only GETs `/models` metadata for generic gateways. OAuth subscriptions have no Auto Configure row at all: `configureOAuthRuntime` copies the catalog straight from the loopback runtime (`runtime.Models()`), so a subscription is never probed as a generic endpoint. Per-slot `[1m]` markers live in `live().oneMSlots`; a slot that kept its model keeps its marker, so re-detection cannot re-open a window the user closed.

### Config, launch, TUI

Claude Code's `/model` and `/effort` capability hints come from the same optional local models.dev reasoning index used by Codex, falling back to explicit runtime reasoning metadata. `internal/claude/effort_capabilities.go` supplies exact per-model `CLAUDE_CODE_MODEL_CAPABILITIES` entries for `effort`, `xhigh_effort` and `max_effort`, covering pool IDs, readable request aliases, `[1m]` variants and explicit canonical model overrides. It does not alter unrelated thinking/tool capabilities or pin `/effort`. An explicit provider Env value wins, and missing/ambiguous metadata leaves native detection intact. Clear old hint entries across process/provider generations, including the long-lived ACP adapter. Native subscription profiles remain on Claude's own model handling. This is a client compatibility hint verified through the official SDK's `supportedModels()` against Claude Code 2.1.296; older clients may ignore it. Claude owns the menu vocabulary: it can enable the base low/medium/high ladder and the xhigh/max extensions, but cannot add minimal/ultra or remove individual base rungs. Do not pretend these hints express arbitrary provider effort lists. The optional real-client test uses `CCL_TEST_CLAUDE` plus `CCL_TEST_CLAUDE_SDK` (the SDK's `sdk.mjs`), an isolated home and a fake local endpoint; it submits no user prompt and rejects inference.

- `internal/config`: `~/.ccl/config.yaml`. `Load` is read-only and normalizes in memory; every write goes through `config.Update(fn)` (file lock, re-read, apply, atomic 0600 write) — cmd code uses `updateProvider` / `replaceProvider`. There are no config migrations: old formats are not read. An OAuth provider's `type` is derived (`provider.EffectiveType`), not persisted; context sizing is the typed `contextPreset` field.
- Global fields: `active_provider`, `acp_provider` (both are name selectors into one `providers` map; empty `acp_provider` follows `active_provider`), `default_claude_provider` (the Claude provider selected by reserved `default`, with the original native configuration as the unset fallback); a fresh install selects `default`, `lang`, `bypass_mode` (not `auto_mode`), `sign_on` (`off` default; ccl writes Claude Code's empty `attribution`, so commits have no Co-Authored-By trailer; `ccl sign --default` also edits `~/.claude/settings.json`), `log_level` (`off` default; `ccl log`). With no provider selected ccl errors; it never builds one from shell `OPENAI_API_KEY` / `ANTHROPIC_*`.
- `internal/claude`: `--settings` outranks the user's own settings, so `outputStyle: Concise`, `language` (from `ccl lang`), `statusLine` (`ccl statusline`; per-provider `statuslineDisabled` opts out) and `modelPicker` (provider slots + pool) are written only when the user's `$CLAUDE_CONFIG_DIR/settings.json` or the project's `.claude/settings{,.local}.json` does not define that key (`user_settings.go`). `effortLevel` / `ultracode` come from `ccl provider effort|ultracode`; `CLAUDE_CODE_EFFORT_LEVEL` is never exported (it pins `/effort`), and `fastMode` is omitted unless on (writing `false` would undo `/fast`). Proxy sessions default `CLAUDE_CODE_ATTRIBUTION_HEADER=0` and `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`; Fast is sent as `X-Ccl-Fast-Mode` via `ANTHROPIC_CUSTOM_HEADERS`, and runtimes strip the hint headers before forwarding. `inheritedEnvToDrop` removes shell `CLAUDE_CODE_USE_*`, model vars, nested-session markers, and the unused credential/custom-header var. Context presets Default / Balanced 500K / 800K are also exported as env because Claude Code has ignored settings-only auto-compact. Provider `Env` overrides defaults except proxy transport keys. Settings files live in `~/.ccl/run` (PID-named, stale ones swept).
- TUI (`cmd/advanced_config*.go` — state, `_view`, `_input`, `_results`, `_async`, `_connection`; `github.com/grindlemire/go-tui`): components implement `Render` / `KeyMap` / `HandleMouse` / `Watchers`; use `tui.WithDisplay(tui.DisplayFlex)`. Single-page set wizard.

### Browser UI (`ccl serve`)

`ccl serve` serves conversations over HTTP + SSE from `internal/webui`. The page is a React + TypeScript + Tailwind app in `internal/webui/frontend` (Vite); `npm run build` writes `internal/webui/web`, which is embedded with `go:embed` and **committed**, because `go install` (and `ccl update --method go`) must build without Node. After changing the frontend, run `npm test && npm run build` there and commit `internal/webui/web` with it; CI's Web UI job fails when the committed build is stale. For live work, run `ccl serve --no-open` and `npm run dev` (Vite on `localhost:5173`, proxying `/api` and `/health` to `CCL_SERVE_URL`, default `http://127.0.0.1:8099`). Event-to-message logic lives in the pure `src/thread.ts` (vitest). Replies render through react-markdown without raw HTML. `go.mod` ignores `node_modules`. One conversation is one ccl terminal session: every turn is a separate Claude Code process (`--print --verbose --input-format stream-json --output-format stream-json --include-partial-messages --permission-mode <mode>`, plus `--permission-prompt-tool stdio` unless the mode is `bypassPermissions`) that continues the previous one with `--resume <claudeSessionId>` from the first `system/init` event, so provider/model/effort apply at turn boundaries and cancel means killing the process. Provider switching only changes conversation metadata and always launches through `claude.PrepareContext` + `Launch.Command`; `ccl serve` never writes `~/.ccl/config.yaml` to switch providers, and `default` follows the same path as a plain `claude` launch. History is `~/.ccl/serve/sessions/<id>/{meta.json,events.jsonl}`; every event carries an increasing `seq`, so a reconnecting stream asks for `?since=` (an EventSource reconnect sends `Last-Event-ID`). The browser accepts server `MessageEvent` records separately from EventSource transport errors: a disconnect reconnects without adding a conversation error or advancing the sequence cursor; a server `error` message remains visible without triggering transport recovery. Every turn ends with exactly one `result` event — Claude Code's own, or one the runner writes when the process reported none (`cancelled: true` for a user stop) — because the browser treats it as the end of the turn. A result's `usage.costUsd` is Claude Code's running total for the session (it continues across `--resume`), so never sum it: the runner stores the difference as `turnUsage` and keeps the last total in `meta.claudeCostUsd`. A turn waiting for a `--max-concurrency` slot returns at once and launches in the background. The process may still be exiting after its `result`, so a non-GET session request (other than cancel and permission answers) first waits up to 15s for a turn whose result is stored (`Timeline.Settle`) instead of answering 409; a turn still working stays busy. `meta.pinned` / `meta.archived` only change where the page lists a conversation: `PATCH` with just those uses `RelabelMeta`, which keeps `updatedAt`, and needs no idle turn (route fields still do). The sidebar groups the active project's conversations (pinned, then by day, archived folded away), its search covers every project, and the project page selects several conversations to archive or delete. A result on a subscription provider (non-empty `oauthProvider`; `default` is not one) carries `subscription: true` (`LaunchSpec.Subscription`), and the page then shows tokens without Claude Code's cost estimate. Each project's defaults for new conversations (provider, model, effort, permission mode) live in `<store>/projects.json` (`projects.go`): `GET /api/workspaces` lists them as `defaults`, `PUT /api/workspaces/<id>/defaults` sets them, and `POST /api/sessions` fills what the request leaves empty from them (a provider deleted since is skipped with its model); the composer edits a new conversation's route before its first message. Below the `sm` breakpoint, the composer exposes separate model and reasoning menus with checked radio options; the model list uses the full scrollable popup height. The reasoning trigger shows L/M/H/X/MAX (a gauge for the default), while its menu keeps full names. Both use the same draft/session route updates and running-turn lock as the desktop selectors. Provider, project and permission-mode selection use the same mobile menu shell and radio-row component, including placement, focus, dismissal and compact styling; choosing a provider still clears the model override. The permission icon remains beside the effort trigger. The project menu retains a separate "open another folder" action; these native selects are desktop-only. The mobile composer places a full-width, 16px text input above a separate action row, with a 60px minimum input height, 44px primary touch targets and bottom safe-area padding. `POST /api/sessions/:id/share` gives a conversation a random 64-hex `shareToken`; `/share/<token>` serves the page, which reads the public `GET /api/share/<token>` (title, folder name only, events, worktree diff) and `…/uploads/<file>`, all with `Referrer-Policy: no-referrer`; `DELETE …/share` revokes it. Cloud sync (`cloud.go`, the settings dialog's Cloud sync tab): `GET /api/cloud` reads remotes and their status through `internal/cloudsync` (each status bounded to 20s; `icloud` is offered on macOS only, and `unavailable` says why Google Drive cannot log in from a build without the OAuth client, which the login refuses up front; the sidebar's avatar opens this tab, with a dot for the primary remote: green in sync, amber otherwise), and every change runs the server's own binary — `ccl cloud login <platform> [alias] --no-browser` through the same login relay as subscriptions (Google Drive completes through ccl's 127.0.0.1 callback from a browser on this machine, or `POST /api/cloud/login/<id> {address}` writes a pasted redirected address to its stdin), and `ccl cloud push|pull [--to|--from alias] [--force]`, `remote use`, `logout` (local only) for `POST /api/cloud/{push,pull,primary,logout}`; a refusal is 409 with ccl's output so the page can offer `--force`. `GET /api/sessions/:id/worktree/diff` is the worktree's diff from its merge base with the base branch (uncommitted tracked changes included, 2 MB cap), which Markdown/HTML exports append. Session responses carry `running` from memory; it is never written to `meta.json`. Attachments upload to `POST /api/sessions/:id/uploads` and live in the session's `uploads/` (the id is a random prefix plus the sanitized name; the type comes from the bytes, never the extension). Every turn writes one stream-json user message on stdin and keeps stdin open until its `result`, then closes it so the process exits: attached png/jpeg/gif/webp up to 5 MB go as base64 image blocks, every other file by path in the text. Permission questions arrive as `control_request` / `can_use_tool` on stdout; they become `permission` events (input redacted, the original kept in memory for the answer) and `POST /api/sessions/:id/permissions` writes the `control_response` (allow with the original `updatedInput` — plus `answers` for AskUserQuestion — or deny with a message; "remember" reuses Claude Code's suggestions with `destination` forced to `session`; plan approval adds `setMode` and stores the mode on the session). Other control requests get an error response so Claude Code never waits. A session's `permissionMode` defaults to `bypassPermissions` when ccl's `bypass_mode` is on, else `default`. `GET …/uploads/:file` serves only those image types inline (everything else, SVG included, downloads) under `Content-Security-Policy: sandbox`. Init events carry `slashCommands` and `mcpServers`; `message_start` usage becomes `context` events (the context ring); unstreamed (sub-agent) assistant text is emitted from the complete message, and sub-agent events carry `parent`, the Task call they belong to; `GET /api/capabilities` returns the latest ones for the composer menus. The page follows `ccl lang` (else the browser language) through `src/i18n.ts`; its layout follows claude.ai/code without its fonts or marks. Workspace tools: `/api/files/*` (list, read, write with an `expectedHash` optimistic lock, search, uploads that never overwrite, raw with `?token=`) resolves every path through `resolve` (symlinks evaluated against the workspace's real path); `/api/git/*` runs git from argv with `GIT_OPTIONAL_LOCKS=0`, paths after `--`, branch names through `check-ref-format`, commit messages on stdin. `/api/claude-sessions` lists Claude Code's own transcripts for the workspace (`~/.claude/projects/<cwd with non-alphanumerics as ->`) and imports one as a conversation that resumes it. Scheduled messages persist in `<store>/schedules.json` and go out through the same `startTurn` as `/messages`. `/api/oauth/login` runs `ccl oauth <name> --no-browser` (the server's own binary) and relays the URL it prints; `/api/mcp` reads Claude Code's MCP configs (never returning env or header values) and changes them only through `claude mcp add-json/remove`. The web terminal (`/api/terminal`, creack/pty, SSE output from a byte offset, POST input) is on by default (`--no-shell` turns it off) and unavailable on Windows.

The settings dialog (`SettingsDialog.tsx`; providers are created and edited in a dialog of their own) writes `~/.ccl/config.yaml` through `config.Update(fn)` for every change — never hand-built YAML; a subscription login started from the page writes through `ccl oauth` itself. `GET /api/config` masks API keys to the last four characters; `PATCH /api/config/providers/:name` treats `apiKey: ""` as "leave it", `null` as "clear it", and any other value as a replacement. `default` is reserved: 403 on edits and deletes. Deleting the active or ACP provider is 409. A running turn keeps the provider snapshot it was started with, so settings changes only affect new turns. `/health` is public; every `/api` route needs `Authorization: Bearer <token>`, while the SSE and events endpoints also accept `?token=` because EventSource cannot set a header. A loopback bind (`--host 127.0.0.1`, the default) requires no token; any other host refuses to start without `--token` or `CCL_SERVE_TOKEN`. The browser opens once the listener is ready unless `--no-open`. `--socket [path]` (default `~/.ccl/serve/ccl.sock`; a bare `--socket` takes no value, so `--socket /path` arrives as the argument) serves the same handler on a Unix socket instead of TCP (`webui.ListenUnix`: mode 0600 in a 0700 directory, a socket another server still answers on is refused, a stale one replaced, the file removed on close) for native clients, opens no browser, and prints one ready line `{"socket","pid","version"}` on stdout (everything else is stderr); `guard` skips the Host/Origin checks for requests on a Unix socket (`http.LocalAddrContextKey`), since no browser page reaches one, while a `--token` still applies. Ctrl+C / SIGTERM cancels the `BaseContext` (open SSE and terminal streams end at once), then `Server.Close` stops schedules, logins, terminals and turns in flight (stored as cancelled) within 3s; a second Ctrl+C exits immediately. Workspaces (`workspaces.go`) are each repeatable `--workspace` (default `.`), every non-hidden directory directly inside a `--workspace-root` (rescanned every 5s), and folders the page added — "open another folder" / "new project" through `POST /api/workspaces {path}` and `GET`/`POST /api/directories` (a folder browser that lists directories only and creates one single-segment folder), persisted in `<store>/workspaces.json`; `--lock-workspaces` refuses both with 403. The page calls workspaces projects (code, API and flags keep `workspace`): the Projects page (`ProjectsPage.tsx`) lists them, and a project's page edits its `CLAUDE.md` (the root one, else `.claude/CLAUDE.md`) and `CLAUDE.local.md` through `/api/files` with the `expectedHash` lock (a 409 offers a reload); unsaved edits ask before the page is left. It also edits `permissions.allow/ask/deny` in `.claude/settings.json` / `settings.local.json` (each change saved at once, other keys kept) and links to the project's MCP connectors. The settings dialog's Instructions tab edits the user `CLAUDE.md` in `$CLAUDE_CONFIG_DIR` (default `~/.claude`) through `GET`/`PUT /api/memory` (`memory.go`; the same hash check via `saveVerified`), the only file outside a workspace the page can write. A new conversation in a git repository may run in a worktree (`worktree.go`): `POST /api/sessions {worktree: true}` runs `git worktree add -b ccl/<first 8 of the session id>` at the project's HEAD under `<store>/.worktrees/<workspace id>/<name>` (outside the project, so its status stays clean; `CLAUDE.local.md` and `.claude/settings.local.json` are copied in), and `meta.worktree` records name, branch, base branch and commit. Turns run there; files/git/terminal/MCP requests add `&worktree=<name>` (validated, resolved under the store only). `GET /api/sessions/:id/worktree` reports ahead/behind/dirty and changed files; `POST …/worktree/merge` runs `git merge --no-ff` in the project only when it has the base checked out, both sides are clean and there are commits (a conflicted merge is aborted); `POST …/worktree/push` pushes with `--set-upstream` to the base's remote (else `origin`). Deleting the conversation removes the worktree (uncommitted changes are 409 unless `?force=1`) and the branch only when merged (`git branch -d`); a turn whose worktree vanished is 409 (`ErrWorktreeMissing`). Requests name a workspace by id (the first 12 hex of sha256 of the real path) — `POST /api/sessions` takes `workspace: <id>` and a path is 400; files/git/claude-sessions/mcp/terminal requests carry `?workspace=<id>` (none means the first; an unknown id is 404). A conversation runs only in the workspace it recorded; when that is no longer served, `/messages` is 409 (`ErrWorkspaceNotServed`). Prompts travel in the stdin message, never through a shell. Without a token, `guard` (guard.go) accepts only loopback `Host` headers (DNS rebinding) and refuses state-changing requests from another site's `Origin`; every JSON write must say `Content-Type: application/json`, and multipart is accepted only on `/uploads` routes.

### i18n layering

User-facing Chinese lives in `cmd/` via `locale.T`. `internal/` must not contain Chinese string literals (`internal/protocol/no_chinese_strings_test.go`); `internal/locale` is the exception.

### Cloud sync

`internal/cloudsync` encrypts `config.yaml` + `auth/*.json` to iCloud / Google Drive under `ccl cloud ...` only (registry v2 in `~/.ccl/cloud`; no v1 layout, passphrase, Keychain, recovery-key or pairing modes). The Desktop OAuth client (Cloud project `93551281893`) is not in source: release ldflags inject `cloudsync.googleOAuthClientID/Secret`; PKCE is the real auth boundary; `appDataFolder` belongs to the Cloud project. The random profile key is stored in the cloud `profile.json` (`account_key`), so `loginFirstRemote` on a new device opens the account's profile (or creates one) with nothing but a login. `--no-browser` (default when `headlessHost()`: SSH, Cloud Shell, Linux without a display) prints the authorization URL and reads the redirected `127.0.0.1` address pasted back (`cloudsync.WithPastedRedirect`), still with the Desktop client + PKCE. Do not reintroduce the OAuth device flow: Google rejects `drive.appdata` there (`invalid_scope`) despite its docs, and `appDataFolder` is per Cloud project, so any other client would see different data.

## Product facts that affect code changes

ccl is a launcher + protocol proxy, not a fork of Claude Code. Extra CLI args after a non-ccl command are passed through.

OAuth public names: `gpt` `gemini` `grok` `qoder` `kimi` `kiro` `workbuddy` `workbuddycn` `autoclaw` `zed` `cursor`. `workbuddy` is www.workbuddy.ai and `workbuddycn` is www.workbuddy.cn: same plugin API and chat protocol, different origin and credential `type` (see `workbuddyDeployment`). Slot defaults: `internal/provider/oauth_defaults.go` (empty slots only; missing catalog entries are cleared at launch).

`bypass` injects `--dangerously-skip-permissions`, except when `--permission-mode` is given or the first arg is a Claude Code subcommand. Provider management lives under `ccl provider` and sync under `ccl cloud`; there are no root shortcuts for them. `ccl doctor` is read-only and bills nothing without `--probe`. `ccl update` verifies the `.gz` asset against `SHA256SUMS`; `--method self|npm|go` is required off a TTY.
