## 工具调用稳定性与模型目录自动刷新

### 模型目录自动刷新

运行中的服务现在会自动检测当前提供方的 context 设置和本地 effort 元数据变化，约一秒内更新模型目录。修改这些设置后，只需重启 Codex 读取新目录，不再需要反复执行 `ccl codex start`。

更新保留已有连接、会话历史、shared/independent 模式和独立模式凭据。端点、凭据、协议及模型路由变更仍通过显式启动重新加载；不会跟随 Claude 的 active provider 自动切换账号。

### 工具名称与流式调用

- Codex 转换层保留 `exec`、`wait`、`tool_search` 等合法的顶层工具名，减少模型复述哈希后缀时出错。命名空间、特殊字符和过长名称仍使用确定性的别名，保持工具区分和历史回放。
- 修复 Chat Completions 流式工具名称被后续分片覆盖的问题。分片、重复名称和累积名称仅在能唯一对应当前声明的工具时接受。
- 流式并行调用在发出第一个工具调用前，检查整批工具名称；不完整、歧义或未声明的名称会报错。
- 损坏工具名称中夹带的思考内容、DSML 标记和其他文本不再原样写入错误提示，也不会被解析成可执行调用。
- 这些改进适用于 shared 和 independent 模式。上游仍可能生成无效调用，CCL 会拒绝执行；不会在已经输出部分响应后静默重试。

首次升级到本版本后运行一次 `ccl codex start`，服务兼容版本 15 会替换旧进程并加载上述改进，保留现有地址与 shared/independent 模式，然后可重试原会话。
