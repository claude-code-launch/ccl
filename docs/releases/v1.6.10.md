## 修复与改进

- npm 发布改为并发：六个平台包同时检查并上传，不再逐个串行等待。此前串行上传让注册表索引延迟被放大了六倍。
- npm 就绪检查绕过注册表 CDN 缓存。注册表元数据带 `cache-control: max-age=300`，且忽略请求端的 `no-cache`，因此刚发布的版本会在 `cf-cache-status=HIT` 后面最多隐藏五分钟；现在每次检查都加唯一查询参数强制回源。`write=true` 同样能绕过缓存，但 install-v1 元数据会返回 406。
- 重复运行时不再误判“尚未发布”：存在性检查直接读回源元数据，避免对已发布的包重复上传并失败。
- 清理 npm 警告：`bin` 字段去掉会被 npm 自动改写的 `./` 前缀；升级 `actions/setup-node` 到 v7，不再写入已废弃的 `always-auth` 配置。
- 升级 GitHub Actions 以消除 Node.js 20 弃用提示：`actions/upload-artifact` v4 → v7、`actions/download-artifact` v4 → v8、`actions/cache` v4 → v6，同时去掉这些旧版本 post 步骤产生的 `punycode` 弃用警告。
