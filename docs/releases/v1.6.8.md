## 修复与改进

- 修复 `ccl update --method npm` 的失败恢复：npm / postinstall 返回非零且命令已损坏时，也会进入二进制恢复；恢复目标提前取自 `npm root -g`，不再依赖可能被 npm 移除的运行文件。必要时恢复缺失的命令链接，并明确提示“二进制已恢复，npm 安装未完成”，不再误报 npm 更新成功。Windows 不原地恢复，给出重试命令。
- 二进制已是最新版本时，显式指定 `--method npm` 仍可修复 npm 包，解决 self 更新后二进制版本与 npm 包版本不一致、再次更新却直接退出的问题。
- npm 安装固定为本次检测到的版本，并带上 `--include=optional --prefer-online`；安装后只验证 npm 实际目标目录中的二进制与命令入口，避免 PATH 上另一个正常的 ccl 掩盖安装失败。
- npm 发布流程同时检查完整及 install-v1 元数据，实际下载平台 tarball 并验证 SHA512，所有平台就绪后才发布 launcher；最后确认 launcher 的 `latest` 已更新。平台包共用等待预算（30 分钟），不再只凭 `npm view` 返回版本号判断可安装。
