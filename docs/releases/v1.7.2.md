## 新功能：`ccl serve --base-path`

把页面和 API 挂在一个路径前缀下，供反向代理按路径转发（代理需保留前缀，不要 StripPrefix）：

```bash
ccl serve --host 0.0.0.0 --no-open --token "$TOKEN" --base-path /chat
# 页面：http://<host>:8099/chat/    API：/chat/api/...    健康检查：/chat/health
```

- 前缀需是普通的绝对路径，例如 `/chat`；`/chat` 会 308 跳转到 `/chat/`，前缀以外只保留根路径 `/health` 给容器探针。
- 页面资源改为相对路径，同一份构建在根路径和任意前缀下都能用；分享链接自动带上前缀。
- 不写 `--base-path` 时行为与之前完全一致。

## 页面令牌改用 `X-CCL-Token` 请求头

网页现在用 `X-CCL-Token` 发送令牌，把 `Authorization` 留给前面的 Basic auth 代理，两层认证可以同时使用。

- 服务端仍接受 `Authorization: Bearer <token>`，脚本和原生客户端无需修改。
- 请求带了 `X-CCL-Token` 时只按它判断；值错误不会再回退到 Bearer。
