## Gemini 工具调用修复与 Claude Code 模型 effort 适配

### Gemini 模型与工具调用

- Gemini 订阅的 Haiku 默认映射改为 `gemini-3-flash`，替换已经不在上游目录中的 `gemini-3.1-pro-low`。已有映射和模型池会在读取时更新，并保留用户设置的 `[1m]` 标记。
- Gemini 3/4 的自动工具调用使用 `VALIDATED` 模式，约束函数名称和参数格式，同时允许普通文本回复。显式禁止、强制或指定工具的选择仍按客户端要求处理。
- 补充 Codex 工具名称映射及 `exec` 原始代码输入说明，减少模型把执行器文档中的嵌套工具误当成独立函数调用的情况。未声明的工具仍会被拒绝。
- 保留工具调用及结果的配对 ID，修复在同一会话中从 Gemini 切换到 Sonnet/Opus 后出现的 `tool_use.id: Field required`。
- 原生工具 ID 和签名历史保持对应关系，兼容旧版本生成的客户端 ID；并行调用同一个工具时，结果仍按各自的 ID 匹配。
- 当前提供方目录之外的 Codex 模型返回明确的 404 提示，避免把旧会话的模型转到另一个提供方。

### Claude Code 的 effort 菜单

Claude Code 的 `/model`、`/effort` 菜单现在读取已有的本地模型推理元数据，按实际模型控制 effort 是否可用，以及是否提供 `xhigh`、`max`。读取失败或没有可靠元数据时，保留客户端原生判断；显式的提供方能力配置仍优先。

适配覆盖模型槽位、模型池、可读别名和 `[1m]` 变体，也会清理切换提供方时残留的能力提示。不会固定 `/effort` 的选择，也不会改动其他工具或 thinking 能力。

Claude Code 原生菜单仍有边界：`low/medium/high` 是固定基础档，无法精确裁成“仅 high”等任意子集，也无法新增 `minimal`、`ultra`。真实客户端的菜单能力回归已在 Claude Code 2.1.296 上验证，未发送模型推理请求。

### 升级后加载修复

更新 CCL 后运行：

```bash
ccl codex start
```

本地服务兼容版本升至 13，启动时会替换仍运行旧代码的服务，并保留原有地址及 shared/independent 模式。只重新构建或更新可执行文件，不会让旧进程自动加载修复。

Claude Code 的菜单适配在重新通过新版 CCL 启动 Claude Code 后生效。
