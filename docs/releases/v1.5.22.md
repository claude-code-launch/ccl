## 变更

- `ccl acp` 改为包装上游 [claude-agent-acp](https://github.com/agentclientprotocol/claude-agent-acp)：ACP 协议、工具、权限、终端、会话持久化由上游实现，CCL 只注入 provider、模型、环境和代理配置，运行中修改配置会在下一条空闲 prompt 前生效。需要 Node.js 22 或更新版本；新增 `ccl acp install`，把 CI 验证的适配器版本装到 `~/.ccl/acp-adapter` 并显示安装进度，同时记住所用的 `node`，Xcode 等 GUI 客户端的 `PATH` 中没有 Node.js 时也能启动。`ccl acp` 不再需要单独安装 Claude CLI；旧版 `~/.ccl/acp/sessions/` 会话映射仅作只读兼容；隐藏的 `ccl acp-permission` 已移除。
- `ccl provider off` 与 `ccl proxy` 互不干扰：独立代理运行中时 `ccl provider off` 会失败并提示先 `ccl proxy stop`；off 期间 `ccl proxy` 必须显式指定 provider（如 `ccl proxy start <name>`）。`ccl ls` 的 `USED BY` 列会显示运行中代理使用的 provider。

## 修复与改进

- 独立代理运行时，代理新增而用户原本没有的设置项不再写成 `null`：Claude Code 遇到 `model`、`modelOverrides`、`fastMode`、`outputStyle`、`language`、`statusLine` 为 `null` 会整体丢弃 `--settings`，导致 `ccl` 启动或 `ccl provider off` 悄悄退回代理配置。
- ACP 会话被删除或归档时释放其 provider 运行时，不再保留到 `ccl acp` 退出。
- 未安装 Claude Code 时，安装提示已本地化；拒绝安装或非终端环境会给出官方安装脚本和 `npm install -g @anthropic-ai/claude-code` 命令；官方安装脚本把 Claude Code 装到 `~/.local/bin` 而该目录不在 `PATH` 中时（如 Google Cloud Shell），`ccl` 每次启动都会直接使用它并提示加入 `PATH`，不再反复询问安装。缺少适配器或 Node.js 版本过低时，`ccl acp` 在 stderr 给出安装命令，`ccl doctor` 显示适配器状态。
- `ccl`、`ccl proxy`、`ccl provider on|off` 的运行时错误只输出一次，不再附带用法说明。
- README 改为中英双语速查。
- CI：在 Linux、macOS、Windows 上用固定版本的真实 `claude-agent-acp` 与 SDK 运行本地模型集成测试。
