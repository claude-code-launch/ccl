## Claude 账号作为 provider，多订阅账号与单次指定

### 多 Claude 账号

- `ccl oauth claude [别名]` 登录的 Claude 订阅账号现在是普通的 provider：`ccl ls` 里能看到，`ccl use <名字>` 切换，网页和 ACP 也能选。不写别名时优先命名为 `claude-<邮箱>`。
- `default` 的含义变了：以前固定是 Claude Code 自己的配置，现在指向「最后一次登录的 Claude 账号」。还没登录过账号的机器行为不变，`default` 仍是 Claude Code 原来的配置。`ccl use default` 使用当前默认账号。
- 新增 `ccl use <名字> --default` 指定默认账号，只改本地选择，不重新打开浏览器授权，令牌照旧由 Claude Code 刷新；`ccl use default --default` 清掉这个指定，回到 Claude Code 原来的登录。
- 删掉被指定为默认的账号会直接报错并提示重新选，不会悄悄换成另一个账号计费。
- 每个账号的设置和历史各自独立，放在 `~/.ccl/claude-accounts/`，不会覆盖原来的 `~/.claude`。模型、effort、环境变量用该账号自己的 Claude 配置（`/model`、`/effort` 或账号目录里的 `settings.json`），`ccl map` / `ccl provider env` 这类只对 CCL 网关 provider 生效的设置会明确拒绝写入账号。
- 账号配置会随 `ccl cloud` 同步，账号目录和凭据不会，新设备需要重新登录。
- 之前 `ccl oauth claude` 保存的账号会自动导入 provider 列表，不需要重登。

### 单次指定 provider

- `ccl --provider <名字> [Claude 参数]` 只对这一次启动生效，不改变当前选择；也支持 `--provider=<名字>` 和 `--provider default`。
- `--provider` 必须写在 Claude 的参数之前。写在后面（比如 `ccl -p ... --provider x`）会被原样传给 Claude Code。

### 启动前的认证检查

- 原生账号启动前会检查账号配置、项目 `.claude/settings*.json` 和额外的 `--settings`：发现网关地址、API key helper 或其他会顶掉订阅凭据的认证配置时停止启动，并指出是哪份文件里的哪个键，不会静默换成别的身份。
- ACP 在切换账号或从账号切到其他 provider 时需要重启 Agent；网页里切换账号请新建对话，因为历史是按账号分开的。

### 网关

- 429 / 5xx 的快速重试改成最多两次（500ms、1s）；上游给了更长的 `Retry-After` 时直接把等待时间透传给 Claude Code，不再提前重试。
- Qoder / WorkBuddy 的凭据请求拒绝跨来源重定向，网络错误里也不再带登录参数；Qoder 只读取自己绑定的那份凭据，并在刷新锁内重新校验类型和启用状态，刷新失败时保留原来的认证错误而不是换成新的失败原因。
