## Codex 路由热重载与 Gemini Antigravity 模型目录发现

### Codex 路由热重载与多提供方挂载

- 已绑定提供方的配置、模型池、槽位映射或上下文设置变更时，运行中的 Codex 服务会在后台切换新的 Runtime 世代并更新路由与目录；新请求自动使用新 Runtime，正在进行的流式输出继续完成。
- 支持同时挂载多个提供方：`ccl codex start <primary> --with-provider <extra>`（可重复传入多个 `--with-provider`）。每个模型固定走各自绑定的提供方与账号凭据，同名显示标签会自动附带提供方标识区分；后续启动和菜单切换保留附加列表，`--with-provider ''` 清空。
- 新增 `ccl codex start --refresh`，在不改写持久配置的前提下主动重新发现上游模型目录并刷新运行中网关。
- 独立模式支持可选远程目录：`ccl codex start --independent --catalog remote`（通过本地网关 `/models` 提供目录，`--catalog local` 切回本地 JSON 目录；shared 模式继续使用合并 JSON 目录）。CCL 的网关路由/目录更新与客户端选择器刷新分离；若 Codex 客户端未立即显示新模型，重启 Codex 即可加载。

### Gemini Antigravity 模型发现与工具回放

- `ccl oauth gemini` 运行时按绑定凭据调用 `loadCodeAssist` 与 `fetchAvailableModels`（携带账号的 `paidTier` / `currentTier` 权益，被拒或不可用时自动回退至项目级查询），并在验证通过后按账号摘要缓存真实 wire ID、上下文/输出窗口及图片模态。新空 Haiku 槽位默认优先使用 `gemini-3.8-flash`。
- 实际返回的 `-minimal`、`-low`、`-medium`、`-high` 模型变体自动聚合为模型家族（如 `gemini-4-argon`、`gemini-3.8-flash`），按客户端 effort 解析到账号拥有的具体 wire ID 并清理冲突的 `thinkingBudget`；显式配置带档位后缀的变体则固定使用该档位并保留变体显示名与元数据。
- 可读显示名（家族名或变体 `DisplayName`，含 `[1m]` 后缀）在协议转换与路由前规范化为目录中的 canonical ID，确保通过显示名请求时同样启用 Antigravity Claude Schema 适配与 Gemini 3/4 `VALIDATED` 工具调用模式。
- 使用按连续 `assistant` 轮次作用域的队列配对带 `thoughtSignature` 的 `thinking` 块与伴随 `tool_use` / `text` 块，支持集中式 `thinking` 块排布并防止跨轮次状态泄漏；当保留签名 `thinking` 块的会话切换到 Antigravity Claude 模型时自动补齐非空调用与结果 ID，避免触发 `tool_use.id: Field required`。

### 升级后加载

更新 CCL 后运行：

```bash
ccl codex start
```

服务兼容版本升至 16，启动时会替换旧进程并保留原有监听地址、shared/independent 模式及附加提供方配置。需要立即重新拉取上游模型目录时可执行 `ccl codex start --refresh`。
