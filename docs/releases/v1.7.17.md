## Codex 模型接入、Cursor 订阅与移动端输入改进

### `ccl proxy` 更名为 `ccl codex`

旧命令已移除，不会作为未知参数转交给 Claude Code：

```bash
ccl codex start [provider]   # 启动或切换 Codex 模型接入
ccl codex status             # 查看当前 provider 与本地地址
ccl codex stop               # 停止并恢复 Codex 原配置
ccl codex start default      # 断开 CCL，恢复 Codex 原有路由
```

`ccl proxy`、`ccl proxy start/stop/status` 现在会直接报错并提示新命令，不会误启动计费会话。macOS 菜单栏、`ccl ls` 的 `USED BY` 和帮助文案也统一改为 Codex 模型接入。

### Codex 模型接入

`ccl codex start` 把当前 provider 的模型加入 Codex 模型选择器，原生 OpenAI 模型和登录保持原样；只有 CCL 白名单中的模型会经过本地代理，转发前会移除 Codex 凭据。

- 默认的 shared 模式保留原生模型，并合并当前 provider 的模型目录。启动、切换 provider 或停止后需重启 Codex 以重新读取目录；代理运行期间切换 provider 不会自动重启 Codex。
- `ccl codex start --independent` 使用独立的 `ccl_proxy` provider，只显示 CCL 模型，自带每会话本地凭据，不依赖 ChatGPT 登录或 OpenAI 额度。OpenAI 额度耗尽后可直接切换到其他 provider。
- `ccl codex start --shared` 恢复原生与 CCL 合并的目录。运行中的启动和菜单切换沿用当前模式；停止后不保留模式，下次默认使用 shared。
- Codex 0.166+ 会按会话创建时的 model provider 继续聊天。独立模式会话绑定 `ccl_proxy`；切到 shared 或停止后，该 provider 被移除，旧会话可能提示 provider 未配置或 `Model unavailable`。要恢复原会话，请重新运行 `ccl codex start --independent` 并重启 Codex；跨模式续接同一段历史请分叉新会话，不要改写会话记录。
- 模型名不再附带 provider 前缀；与原生模型同名时加 `CCL` 标记。WorkBuddy 中同名但内部版本不同的模型合并为一项，旧路由仍然有效。
- 原生模型目录取自现有 Codex 目录、`models_cache.json` 或已安装 Codex 的 bundled catalog，不写死模型名。原有自定义 provider 或默认 profile 的目录覆盖会明确报错，不会被静默改写。
- macOS 菜单栏可切换当前 provider、停止接入；切换成功只更新 CCL 的选择，仍需重启 Codex 载入新目录。无桌面环境可设置 `CCL_PROXY_NO_MENUBAR=1` 关闭菜单栏。
- 异常退出后，下次运行任意 `ccl` 命令会按 `~/.ccl/proxy/state.json` 自动恢复。停止和恢复只还原代理写入且未被用户修改的字段。

### 推理档位、图片与工具搜索

- 转换模型的 effort 档位改为按模型读取 models.dev 元数据，不再统一成低、中、高。OAuth 登录或确认保存 `ccl set` 时会刷新；也可运行 `ccl set --refresh-models` 单独更新。刷新后重新执行 `ccl codex start` 并重启 Codex。
- 网络失败时使用 `~/.ccl/cache/modelsdev.json` 的最后有效快照；没有匹配数据时保留兼容档位，不会凭空增加或删减已知档位。
- Qoder 的可用 effort 从其模型目录读取，并随请求发送 thinking 与 `reasoning_effort`；未列出的档位会映射到该模型实际支持的档位。Gemini 高于 high 的档位映射为 high。
- 支持图片的 Qoder、WorkBuddy 和 Responses 模型会在 Codex 中开放图片输入；工具结果里的截图也会转成后续消息，而不是丢弃或重复成文本。
- 转换模型支持 Codex 客户端工具搜索：CCL 只把搜索声明为普通函数，由 Codex 检索本地工具并返回选中定义，不再一次发送全部延迟加载工具。工具执行与权限检查仍由 Codex 负责。

### 上下文、跨模型续接与输出预算

- Codex 的 CCL 模型沿用 provider 的上下文设置：Default 为 200K，模型带 `[1m]` 时为 1M；Balanced 为 500K / 800K，均在 85% 自动压缩。转换模型由 CCL 生成可回放的压缩摘要，原生 Responses 模型保留上游压缩。
- shared 模式可在原生 GPT 与转换模型之间切换。原生 GPT 的加密压缩内容无法在本地解密；转换模型会校验同一会话的本地记录和压缩项，恢复有边界的可见历史摘录并提示旧细节可能缺失。缺少匹配记录或内容不一致时会明确报错。
- 历史中引用了当前未声明的工具时，只作为文本历史保留，不会伪装成可调用工具。桌面端没有 `call_id` 的命名工具通知也按文本处理。
- 修复 Codex 转换请求未提供输出上限时被按 4K 截断的问题。现在优先使用模型公告的输出容量，未知时使用 32768；客户端显式设置的上限仍原样保留。
- 真正耗尽输出预算时仍返回 `response.incomplete` 和 `max_output_tokens`，不会把截断伪装成完整回复。模型容量过小、无法容纳所选推理档位时会直接报错说明原因。

### Cursor 订阅

```bash
ccl oauth cursor [alias]
```

Cursor 现在是普通订阅 provider，可在终端、ACP 和网页中选择；登录由 cursor.com 的 PKCE 流程完成，不需要安装或启动 Cursor CLI。

- CCL 直接与 Cursor 的 agent 流通信，Claude Code 仍负责工具循环；Cursor 自带的 shell、读文件、搜索等内置工具会被拒绝，实际工具调用由 Claude Code 执行并检查权限。
- 工具调用期间保持上游流，下一次请求用工具结果继续，而不是重放整段对话。
- 模型目录读取失败时使用兼容模型列表并标记为回退目录，不会覆盖已有的有效目录。

### 网页与移动端

- 手机上的输入框改为全宽独立一行，操作按钮单独排列，最小输入高度 60px，主要触控目标 44px，并适配底部安全区。
- 模型与推理档位在手机上合并为锚定单选菜单，支持分组滚动、选中状态和键盘关闭；桌面端选择器不变。
- 修复网页服务端错误事件与 EventSource 断线重连混淆的问题。临时断线不再插入虚假的会话错误，也不会推进事件序号；重连会从最后一个已收到的事件继续。服务端真实错误仍会显示，但不会触发重连。
