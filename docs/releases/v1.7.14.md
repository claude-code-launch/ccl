## 修复 WorkBuddy 同名显示名把请求打到不可用模型

### 问题

在模型选择器里切到「Hy4 preview」时，请求被上游拒绝：

```
API Error: 400 OpenAI Chat Completions upstream returned HTTP 400:
{"code":11102,"msg":"model [hy4-preview-x] service info not found", ...}
```

同一显示名下的 `hy4-preview` 本身是可用的。

### 原因

v1.7.13 把 catalog 显示名注册成请求别名，但多条 catalog 可以共用一个显示名（`Hy4 preview` 同时挂在 `hy4-preview`、`hy4-preview-x` 上）。别名表后写覆盖先写，选择器发出的「Hy4 preview」被映射到聊天接口并未接入的 `hy4-preview-x`。

### 修复

- 技术 ID 先注册，显示名后注册；已被占用的别名不再转让。
- OpenAI Chat 运行时的 `modelRoute` 改为先到先得，避免其它网关出现同样的后写覆盖。

只影响模型别名解析，协议转换不变。
