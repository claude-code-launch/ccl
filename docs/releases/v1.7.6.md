## 新功能：终端里继续的会话同步到页面，子代理单独一列

### 页面跟随终端里的会话

在终端里 `ccl --resume` 继续同一个对话时，页面现在会跟着 Claude Code 的会话记录同步：你在终端里输入的消息、Claude 的回复、工具调用、子代理都会出现在页面上，不需要重新导入，也不会把页面误标成"正在工作"。

- 打开着对话页时每 2 秒检查一次；没有 `turn_duration` 的 print 模式会话，静默 2 分钟后视为该轮结束。
- 页面自己发起的回合会暂停同步，避免同一条消息出现两次；回合结束后跳过这段自己写入的内容。
- 导入终端会话和持续同步用的是同一套回放逻辑，子代理的后半段不会再丢。
- 同步进度保存在会话目录的 `mirror.json`。

### 子代理面板

标题栏新增子代理按钮，列出主对话和每个子代理：类型、交给它的任务、运行时长、输出 token、步数，还有几个正在运行就显示几。

- 点某个子代理，主界面切换成它自己的对话（它收到的提示词、每一步工具调用和最后结论）；点「← main」回到主对话。
- 运行中的是转圈，结束后显示耗时；被 TaskStop 或中断的显示"已停止"。

### 其他修复

- 运行中的子代理状态现在实时推送（`task` 事件此前不在页面订阅的事件类型里，只能刷新后才看到）。新增的测试会检查 Go 端的每种事件都在页面的订阅列表里。
- 子代理的步骤在回合结束时不再误标成红色失败。

### 变更：`ccl serve` 默认使用随机端口

`ccl serve` 不写 `--port` 时由系统分配空闲端口，启动时打印实际地址，同时开多个实例不再冲突。需要固定地址仍可 `ccl serve --port 8099`；`npm run dev` 的转发地址默认仍是 `http://127.0.0.1:8099`，本地开发请显式指定端口或用 `CCL_SERVE_URL`。
