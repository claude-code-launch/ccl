## 修复 WorkBuddy 显示名模型报 400 `model service info not found`

### 问题

在 VS Code 的 Claude Code 扩展里用 WorkBuddy，模型选择器切到「快速 / 均衡 / 极致」这类中文显示名后，请求被上游拒绝：

```
API Error: 400 OpenAI Chat Completions upstream returned HTTP 400:
{"code":11102,"msg":"model [快速] service info not found", ...}
```

### 原因

模型选择器把 catalog 的显示名（`快速`）当作请求 ID 发给代理，但 WorkBuddy 的 `modelRoute` 只注册了技术 ID（`fast-model`），显示名找不到映射，被原样转发给上游，上游只认技术 ID。

### 修复

`buildWorkBuddyRoutes` 为每个有显示名的 catalog 模型额外注册一条 `显示名 → 技术 ID` 路由，与技术 ID 自身并存。其他 provider 的目录显示名同样经过这一层映射，因此一并受益。

只影响 WorkBuddy 路由表的构建，协议转换逻辑不变。
